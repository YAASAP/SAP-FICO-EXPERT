Migration S/4HANA : pièges Universal Journal (ACDOCA, FINS_ACDOC_CUST)

S/4HANAACDOCAMigrationFINS_ACDOC_CUSTDocument splitting

Symptôme

Erreurs ou données incomplètes après migration ECC vers S/4 : messages FINS_ACDOC_CUST1xx, IW41 qui échoue avec FINS_ACDOC_CUST602 (« FICO config is pending »), BALANCE_CCODE, champs ACDOCA vides.

Cause

Champs clients non repris dans le catalogue de champs ACDOCA, ledger non reconnu comme ledger du Journal Universel, catégories de transaction métier non paramétrées, ou splitting incohérent à la migration.

Solution (fils et KBA)

  • IW41 : catégorie de transaction RMRU absente, message FINS_ACDOC_CUST602 : la note 3269873 a résolu le cas en projet de migration (réponse du fil).
  • FINS_ACDOC_CUST103 / 106 / 108 : un champ n'est pas repris dans le catalogue ACDOCA. Retirer le champ des données ou corriger le mapping de migration.
  • FINS_ACDOC_CUST107 : le ledger utilisé n'est pas un ledger du Journal Universel : vérifier la configuration des ledgers.
  • BALANCE_CCODE : consulter le KBA 3668034 (FAGL_SPLINFO_VAL incorrecte pour documents migrés).
  • Autres KBA utiles : 2848473 (ACDOCA-BSCHL vide), 3461202 (écarts BSEG-MENGE/ACDOCA-MSL), 3204302 (BWTAR/BWKEY non remplis), 3663095 (ACDOCA-AWITEM vide).

Pièges

Piège BSEG n'est plus alimentée par l'amortissement (AFAB/AFABN) depuis la 1809 : les écritures d'amortissement sont dans ACDOCA (note 2383115).
Piège ACDOCA contient les reports de solde et lignes de correction de migration, pas BSEG.
Piège Les totaux CO primaires/secondaires n'existent plus : tout est dans ACDOCA.
Piège Désactiver le PCA classique ne demande pas de migrer GLPCA/GLPCP/GLPCT vers ACDOCA (note 2425255) : le PCA est mappé dans le Journal Universel par défaut.

Tips

Tip Faire un cycle de migration complet de test avant le cut-over et garder la liste des KBA FIN-MIG.
Tip Valider les champs clients du catalogue ACDOCA dès la phase de cadrage.
