Architecture · anatomie d'un IDoc

Un IDoc est un conteneur à trois blocs : contrôle, données, statuts

Un IDoc (Intermediate Document) est un document de données structuré, stocké en base avant d'être envoyé ou posté. Comprendre ses trois blocs règle la moitié des diagnostics.

Le enregistrement de contrôle dit qui envoie quoi à qui. Les enregistrements de données portent le contenu métier, segment par segment. Les enregistrements de statut racontent la vie du document : créé, envoyé, posté ou en erreur.

Les trois blocs d'un IDoc et leurs tables
BlocTableContenuChamps à connaître
ContrôleEDIDCUn enregistrement par IDoc : émetteur, destinataire, type, direction, statut courantDOCNUM (numéro), STATUS, DIRECT (1 sortant, 2 entrant), MESTYP, IDOCTP, CIMTYP, SNDPRN, RCVPRN
DonnéesEDID4Une ligne par segment, hiérarchisée, avec les valeurs dans un champ texteSEGNAM (nom du segment), SEGNUM, PSGNUM (père), SDATA (1000 caractères)
StatutEDIDSL'historique : une ligne par changement de statut, avec le message d'erreurSTATUS, STATXT, STAMID/STAMNO (message), STAPA1..4 (variables), date et heure

Trois notions qu'on confond tout le temps

  • Type de message (message type, ex. INVOIC, DEBMAS) : le sens métier. Il pilote le choix du traitement.
  • Type de base (basic type, ex. INVOIC02) : la structure technique, c'est-à-dire la liste hiérarchique de segments. Un type de message peut se réaliser sur plusieurs types de base (versions successives).
  • Extension (ex. ZINVOIC_EXT) : des segments client ajoutés à un type de base standard, sans le modifier. Elle se renseigne dans le champ CIMTYP.
  • Segment : un bloc de champs. Les segments standard commencent par E1 (ex. E1EDK01, en-tête de document), les segments client par Z1. La zone de données d'un segment est limitée à 1000 caractères.

PiègeUn même segment (ex. E1EDKA1) peut se répéter avec des qualifiers différents (PARVW, QUALF, IDDAT). Quand une valeur « manque », vérifiez d'abord le qualifier et pas seulement le nom du segment.
